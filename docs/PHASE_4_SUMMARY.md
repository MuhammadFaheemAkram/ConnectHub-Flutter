# Phase 4 — Post Detail + Comments + Create Post

> A beginner-to-intermediate friendly write-up covering:
> - what shipped in Phase 4, and why;
> - the Flutter / Dart concepts it demonstrates;
> - how the Android and iOS editions solved the same problems.

---

## 🎯 Phase Goal

Phase 4 turns posts into conversations:
- **Post Detail:** a cached post shows at once, then refreshes, with a preview of its latest comments and a comment input.
- **Comments:** the full list, oldest first; your own comments can be deleted (with a confirmation), optimistically and with a rollback.
- **Create Post:** a full-screen form with a live `n/280` counter and a "Discard post?" guard; the post goes to the server, then heads the Feed.
- **Counts that agree everywhere:** adding or deleting a comment moves the count on the detail screen and on the Feed card at the same time, because both read the same cached row.

It is also the first **schema change**: drift v2 adds `comments`, with a migration generated by `drift_dev make-migrations` and tested on every upgrade path.

## 🧱 What Was Implemented

- **Package:** `characters` (the 280-character limit counts what people see).
- **Fake backend** (`core/network/`)
  - `FakeServer`:
    - `getPost`, and `createPost` (authored by the token's user; trimmed; the newest post, so it heads page 1);
    - `getComments` (oldest first), `addComment`, `deleteComment`;
    - only a comment's author may delete it; anyone else gets a 404, as many real APIs answer;
    - requests that break the rules (blank, over 280 characters, a bad image URL) are refused, as a real API would answer 400.
  - `CreatePostRequestDto` (a request body: `toJson` only, with `imageURL`).
  - `FeedApiService` gains `getPost` / `createPost`; new `CommentApiService` / `FakeCommentApiService` (500 ms reads, 350 ms writes).
- **drift v2** (`core/database/`)
  - `comments` (→ `posts` `ON DELETE CASCADE`, → `users`); `CommentsDao` (the JOINed list, mirroring a refresh, add, optimistic remove and restore, the post's count).
  - `PostsDao` gains `watchPost`, `isCached`, `deletePost` and a shared `readPost` row reader.
  - `FeedDao.appendToFeed` became `addToFeed` (a created post joins the window too).
  - `CacheDao.clearAll` wipes `comments` first.
  - `schemaVersion` 2; `make-migrations` exported `drift_schema_v2.json` and generated `app_database.steps.dart` (`stepByStep`) and the migration tests in `test/drift/`.
- **Domain:** `Comment`; `CommentRepository`; `PostRepository` gains `watchPost`, `refreshPost`, `createPost`; use cases `WatchPost`, `RefreshPost`, `CreatePost`, `WatchComments`, `RefreshComments`, `AddComment`, `DeleteComment`.
- **Data**
  - `CommentRepositoryImpl`: mirrors the server; fetches the post first when a deep link opens comments of a post that isn't cached; add (pessimistic) and delete (optimistic, rolled back); `isMine` from the session.
  - `PostRepositoryImpl`: a 404 removes the cached post (and, by cascade, its comments, bookmark and feed place); `createPost` adds the server's copy to the feed window.
- **Design system:** `CommentTile` ("You", ⋮ → Delete), `CommentComposer` (the "Add a comment…" bar), `CharacterCounter`; `BackToFeedButton` works without a router (in view tests).
- **Screens**
  - Post Detail: `PostDetailCubit` (`@factoryParam postId`), loading / error / not found / loaded, the 3 latest comments and "View all N comments".
  - Comments: `CommentsCubit` (`@factoryParam postId`), pull to refresh, delete with confirmation, scroll to a sent comment.
  - Create Post: `CreatePostCubit`, a full-screen dialog, the counter, `PopScope` + "Discard post?".
- **`firstValue`** (`core/common/first_value.dart`): reads a stream's current value without waiting for its cancel (see Interview Notes).
- **Validators:** post content (required; ≤ 280 characters as people count them) and image URLs (optional; `http`/`https` with a host).
- **Tests:** 352 in total (116 new).

### Differences from the plan

- **Adding a comment is not optimistic**, as the spec's screens describe it (a spinner on Send; the text stays on failure). Deleting is optimistic.
- **A 404 for someone else's comment**, rather than a 403: the spec's error vocabulary has no "forbidden", and a 401 would wrongly end the session.
- **Server-side validation failures** surface as the generic "Something went wrong" (`FormatException` → `UnknownException`), because the client validates first.
- **`characters`** joins the dependencies (not in the spec's list) for an emoji-safe 280 limit.

## 💙 Flutter / Dart Concepts Demonstrated

- **A schema migration, generated and tested**
  - `drift_dev make-migrations` exports each version (`drift_schemas/`), then generates `stepByStep`: each step receives the schema *as it was at that version*, so an old step keeps compiling and working however the tables change later.
  - The generated test opens a database exactly as v1 left it, migrates it, and compares the result with the exported v2. A data-integrity test checks that cached rows survive. Removing the step makes both fail (checked).
  - On the simulator, the installed v1 database upgraded in place: `PRAGMA user_version` 2, and all 17 cached posts kept.
- **Runtime parameters through DI:** `@factoryParam` → `getIt<PostDetailCubit>(param1: postId)`.
- **Mirroring the server:** a refresh upserts what came back *and* deletes what the server no longer has (`isNotIn`), in one transaction, and a 404 removes the cached copy.
- **Foreign keys meet deep links:** a comment needs its post, so the repository fetches the post first when it isn't cached.
- **Optimistic delete with rollback** (`removeComment` returns what it removed; `restoreComment` puts it back) versus a **pessimistic add** (no server id until the server answers).
- **`PopScope`:** `canPop` is false while a draft exists; `onPopInvokedWithResult` asks first. `Navigator.pop` (what `context.pop()` calls) ignores it, so closing after publishing or a confirmed discard isn't blocked.
- **UI-owned state stays in the View:** the composer's `TextEditingController` and the list's `ScrollController`; the Cubit sends a one-time effect (`sentCount`) and the View clears the field and scrolls.
- **Counting characters:** `String.length` counts UTF-16 code units ("👍🏽" is 4); `characters` counts what a person sees (1).
- **Testing**
  - Mocked Cubits with `whenListen` over a `StreamController`, to emit a state at a chosen moment.
  - `ensureVisible` for widgets below the fold; finders scoped to one card (`find.descendant`).
  - Regression tests checked to fail without their fix.
- **Three traps** (now conventions §11.26–11.28)
  - injectable reports an unregistered dependency only as a build *warning*; the generated code compiles and fails at runtime.
  - Under the fake async of widget tests, a drift stream's `cancel()` never finishes, and `Stream.first` waits for it. The Cubits read with `firstValue` instead.
  - `make-migrations` writes `migration_test.dart` only once, with a template data test: the file is ours to fill and extend.

## 🔁 Data Flow (this phase)

```
PostDetailPage ── getIt<PostDetailCubit>(param1: postId)..load()
   ├─ watchPost(postId) ───────▶ PostsDao: posts ⨝ users ⟕ bookmarks WHERE id = postId
   ├─ watchComments(postId) ───▶ CommentsDao: comments ⨝ users, oldest first ─▶ the last 3
   └─ refresh: refreshPost ∥ refreshComments
        refreshPost ─▶ API getPost ─▶ upsert │ 404 ─▶ deletePost (cascades to comments, bookmark, feed)
        refreshComments ─▶ API getComments ─▶ (post not cached? refreshPost first) ─▶ replaceComments + count

Send ─▶ AddCommentUseCase (trims) ─▶ API addComment ─▶ CommentsDao.addComment (+1) ─▶ streams re-emit
          ─▶ the Cubit re-reads the list (firstValue), then sentCount + 1 ─▶ the View clears the input

Delete (own) ─▶ removeComment (−1, at once) ─▶ API deleteComment ─▶ ok │ restoreComment (+1) + SnackBar

New post ─▶ CreatePostCubit (validates, trims) ─▶ API createPost ─▶ FeedDao.addToFeed ─▶ the Feed re-emits ─▶ page closes
```

## 🤖🍏 Android / iOS Comparison

| Concept | Android (Kotlin) | iOS (Swift) | Flutter (Dart) |
|---|---|---|---|
| Schema changes | Room v4, hand-written `Migration(1, 2)` … | SwiftData, no versioned schemas | drift `make-migrations`: exported versions, generated steps, generated tests |
| Comment delete | local only (DAO delete, count −1) | local only (`try?`, errors ignored) | server call, optimistic, rolled back on failure |
| Comment add | the API, then Room (count +1) | the service, then SwiftData, with the author's name copied into the row | the server, then drift (+1); the author is a JOINed reference, so a rename shows everywhere |
| Who may delete | `isOwnComment` checked locally | locally | the server (404 for anyone else); the UI offers it only on your own |
| Comment counts | stored, ±1 locally | stored | derived by the server; the cache mirrors it and moves ±1 with your own changes |
| 280 limit | `content.length` (UTF-16), and `take(280)` truncates | `content.count` (characters) | `characters.length`, validated, never truncated |
| Leaving a draft | – | – | `PopScope` + "Discard post?" |
| Post not found | – | – | "This post is no longer available.", and the cached copy is removed |

The closest match is iOS's character counting. The Flutter edition adds what both native editions skipped: a server that owns comments, rollback, and a migration that is generated and tested.

## 🎤 Interview Notes

**Q: How do you ship a schema change safely?**
A: Bump `schemaVersion`, run `drift_dev make-migrations`, and write the step in `stepByStep`. The tool exports the new schema version and generates a test that builds a database exactly as each older version left it, migrates it, and compares the result. Add a data-integrity test for anything that moves data. In this phase, removing the `createTable` step made both tests fail.

**Q: Why does each migration step get a `schema` argument?**
A: It is the schema *as it was at that version*. If a step used today's table classes, changing a table in v5 could silently break the v1 → v2 step. A versioned snapshot keeps every step correct forever.

**Q: Your comments have a foreign key to posts. What breaks with deep links?**
A: Opening `/posts/p10/comments` directly can load the comments before the post is cached, and the insert violates the foreign key. The repository checks for the post and fetches it first. The DAO also skips writes for a post that left the cache (e.g. a logout racing a request), so nothing fails or comes back.

**Q: Why is adding a comment not optimistic, when deleting is?**
A: An added comment has no server id yet, and the screen's job is to keep the text if sending fails. A spinner on Send and keeping the text is honest and simple. A delete has everything it needs (the row) to undo itself, so it can disappear at once and come back on failure.

**Q: Why does the server answer 404 when you delete someone else's comment?**
A: A 403 would confirm that the comment exists. Many APIs (GitHub's, for one) answer 404 for things you may not touch. And it mustn't be a 401, which would end the session.

**Q: How does the discard dialog avoid blocking the page from closing after a successful post?**
A: `PopScope` only intercepts *maybe*-pops: the back gesture, the close button. Closing after publishing calls `pop()`, which always pops. `canPop` also becomes true once the status is `success`.

**Q: A widget test hung forever on `stream.first`. Why?**
A: `Stream.first` completes only after it has cancelled its subscription. Under the fake async of widget tests, a drift stream's cancel never finishes, so `first` never returns. It works in the app. A tiny `firstValue` helper completes on the first event and cancels in the background. A test with `first` instead fails, which proves the point.

**Q: Why count characters with `characters`?**
A: `String.length` counts UTF-16 code units, so "👍🏽" counts as 4. People count one. The counter and the validation must agree with what people see.
